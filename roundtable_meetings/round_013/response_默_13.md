# 默的回应 — Turn 13：从"下载文件"到"工作流跟踪"

## 诚卓的原话

> "产品上就不能说给他下载一份什么文件了，得在产品上展示这个操作手册，还能跟踪整个工作流，就好像Meegle？好像Jira？"

---

## 一、这个想法把产品提了一个维度

之前我们一直在想的是：

> 用户付$99 → 下载一份PDF操作手册 → 自己照着做

诚卓现在说的是：

> 用户付$99 → 进入一个在线工作流面板 → 每一步是什么、做到哪了、下一步是什么、一目了然 → 持续跟踪直到钱追回来

这不是微调，这是**产品形态的根本升级**——从"文档"变成"工具"。

### 类比

| 旧形态 | 新形态 |
|--------|--------|
| 像买了一本攻略书 | **像打开了一个项目管理面板** |
| 读完了扔一边 | **每天打开看进度** |
| 一次性消费 | **持续使用** |
| 被动信息 | **主动引导** |

### 这比PDF好在哪？

| 维度 | PDF操作手册 | 工作流面板 |
|------|-----------|-----------|
| **进度感** | 没有。下载后不知道自己做到哪了 | **一目了然。2/7步已完成** |

| **粘性** | 极低 | **极高。每做完一步都想继续** |

## 三、这直接解决了Turn 07的"意愿问题"

Turn 07我们讨论的核心问题是：**用户知道了路但不愿意走怎么办？**

工作流面板几乎是最好的解决方案：

1. **把大任务拆成小步骤**：不是"你要去仲裁"（太大太吓人），而是"今天你就找一下冻结通知邮件"（很小很具体）
2. **进度可视化**：每完成一步就有进度感，2/7 → 3/7 → 4/7，心理上不想半途而废
3. **下一步永远明确**：不需要用户自己想"接下来干嘛"
4. **时效倒计时**：创造紧迫感但不是恐吓
5. **阶段解锁**：完成感 + 不跳步的约束

这比PDF + "建议你去找律师"的推动力强10倍。

## 四、技术上怎么做？

### 不需要做一个Jira

不需要那么重。本质上就是：

| 组件 | 功能 | 技术复杂度 |
|------|------|-----------|
| **任务列表** | 7个步骤，每步有子任务 | 低（数据库几张表） |
| **状态管理** | 每个任务的完成/进行中/待开始 | 低（状态字段） |
| **进度条** | 2/7可视化 | 极低（前端组件） |
| **材料勾选** | 证据清单，用户勾选"已有/未找到" | 低（checkbox） |
| **阶段解锁** | 上一步完成后解锁下一步 | 低（条件判断） |
| **倒计时** | 时效剩余天数 | 极低（日期计算） |
| **模板下载** | 在对应步骤提供文书模板 | 低（文件托管） |
| **律师入口** | 在步骤5展示推荐律师 | 低（静态列表） |

### 技术栈不变

还是Next.js + Supabase + Vercel，只是：
- 加一个用户认证（Supabase Auth，免费）
- 加几张数据库表（cases, tasks, evidence_checklist）
- 前端多一个Dashboard页面

### 额外开发时间

在原来4周基础上，工作流面板大概多需要**1周**。所以5周出Beta。

## 五、定价怎么调？

工作流面板的存在改变了定价逻辑——用户不再是"买一份文件"，而是"开通一个持续使用的追回面板"。

### 方案A：一次性解锁

| 价格 | 包含 |
|------|------|
| 免费 | 步骤1（案件自检）|
| $99 | 解锁步骤2-7（完整追回面板 + 路线图 + 证据清单 + 文书模板 + 律师入口）|

### 方案B：分层解锁（衡上一轮建议的思路）

| 价格 | 包含 |
|------|------|
| 免费 | 步骤1（案件自检）|
| $99 | 解锁步骤2-3（路线图 + 证据管理面板）|
| $199 | 解锁步骤4-5（文书模板 + 律师交接包）|

### 方案C：订阅制（更长期视角）

| 价格 | 包含 |
|------|------|
| 免费 | 步骤1（案件自检）|
| $29/月 | 全部功能，持续使用直到追回 |

### 我倾向方案A

原因：
1. 用户已经被冻了钱，再让他月月付$29心理上不舒服
2. 分层解锁（方案B）会让用户在步骤3结束后犹豫要不要再花$199
3. $99一次性解锁最干脆，转化率最高
4. 对独立开发者来说，一次性收费最简单

## 六、这还带来一个巨大的副产品：数据飞轮

用户在面板上的每一次操作都是数据：
- 哪些步骤用户卡得最久？→ 优化产品
- 哪些证据用户最难找到？→ 加提示/指南
- 多少用户走到了步骤5（联系律师）？→ 验证Turn 07的"意愿假设"
- 多少用户最终完成了仲裁？→ 真实成功率数据

这比PDF下载后完全失联好无数倍。

---

## 七、总结

| 维度 | PDF操作手册 | 工作流面板 |
|------|-----------|-----------|
| 产品形态 | 一次性文档 | **持续使用的追回管理工具** |
| 用户体验 | 下载→阅读→靠自己执行 | **登录→看进度→做下一步→看更新** |
| 行动推动力 | 弱 | **强（进度条+解锁+倒计时）** |
| 用户粘性 | 极低 | **极高** |
| 数据收集 | 无 | **完整的用户行为数据** |
| 技术复杂度增加 | — | +1周开发 |
| 与半托管的衔接 | 难 | **自然过渡（面板上加"需要帮助？"入口）** |

### 一句话

**FreezeGuard不是给用户下载一份文件，而是给用户打开一个"追回我的钱"工作台。像Meegle管项目一样管追回流程。**

这才是一个让人愿意付$99、持续使用、并且自然过渡到半托管的产品形态。
