## 一、支付：个人能不能接？钱能不能打回来？

### Stripe

| 问题 | 答案 |
|------|------|
| 个人能接吗？ | **不能直接用中国大陆身份注册**。需要：护照+香港银行账户，或ITIN+美国银行账户 |
| 要企业资格吗？ | 不需要企业，个人账户（Individual Account）可以，但需要海外银行账户 |
| 钱能打回国内吗？ | **不能直接到大陆银行卡**。打到香港/美国银行账户，再转回国内 |
| 手续费 | 2.9% + $0.30/笔 |
| 开户难度 | 中等。需要办港卡（现在不难，招行/中银香港都可以远程开）|

**结论**：Stripe可以用，但需要一个香港银行账户作为中转。

### 支付宝

| 问题 | 答案 |
|------|------|
| 个人能接吗？ | **能**。支付宝有"个人商户"通道，身份证+银行卡即可申请 |
| 要企业资格吗？ | 不需要营业执照 |
| 钱能打回吗？ | **直接到你的支付宝/银行卡**，T+1到账 |
| 手续费 | 0.6%/笔 |
| 限制 | 单笔≤500元（个人收款码），开通当面付可更高 |

### 微信支付

| 问题 | 答案 |
|------|------|
| 个人能接吗？ | **商户号需要企业/个体户**。个人收款码可以用但不支持API对接 |
| 要企业资格吗？ | 商户号需要。但办个个体户营业执照很简单（淘宝代办100-200块，1-3天）|
| 钱能打回吗？ | **直接到你的银行卡** |
| 手续费 | 0.6%/笔 |

### Paddle（替代方案）

| 问题 | 答案 |
|------|------|
| 个人能接吗？ | **能**。支持Individual账户，中国大陆地址可用 |
| 要企业资格吗？ | 不需要 |
| 钱能打回吗？ | 通过Payoneer（派安盈）提现到国内银行卡 |
| 手续费 | 5% + $0.50/笔（比Stripe贵，但它帮你处理全球税务） |
| 审核 | 较慢（1个月左右），需要网站+隐私政策+服务条款 |
| 优势 | **作为你的"记录商户"（Merchant of Record）**，帮你处理全球增值税、退款、发票 |

### 我的推荐方案

**V1分两条线**：

| 用户群 | 支付方式 | 理由 |
|--------|---------|------|
| **海外用户/有国际卡的中国卖家** | Stripe（通过港卡中转）| 最主流，信任度高 |
| **国内用户** | 支付宝当面付（个人商户）| 零门槛、钱直接到账 |

**如果嫌Stripe麻烦**：用Paddle代替Stripe。虽然手续费贵一倍（5% vs 2.9%），但Paddle帮你处理税务、退款、发票，而且个人身份+大陆地址就能申请。

**V1不做微信支付**——需要营业执照才能对接API，除非你办个个体户（也不难，但增加前期事务）。

## 二、后端部署在哪？

### 先回答核心问题：买服务器还是Serverless？

**答案：Serverless。**

FreezeGuard V1的后端逻辑非常简单：
- 问卷提交 → 规则引擎判断 → 返回结果
- 用户认证 → 读写数据库
- 支付回调 → 更新状态

这些全是**短请求、低计算**，完全不需要一台24小时跑着的服务器。

| 维度 | 买服务器（VPS） | Serverless |
|------|---------------|------------|
| 月成本（V1流量） | $5-20/月（哪怕没人用也要付） | **$0**（免费额度内） |
| 运维 | 需要自己管系统更新、安全补丁 | **零运维** |
| 扩展 | 手动扩容 | **自动扩展** |
| 冷启动 | 无 | 有（但Next.js在Vercel上极快） |

### 具体方案对比

| 方案 | 前端 | 后端API | 数据库 | 月成本（V1） | 中国访问 |
|------|------|---------|--------|-------------|---------|
| **A. Vercel + Supabase** | Vercel（全球CDN） | Next.js API Routes（Vercel Functions） | Supabase（托管PostgreSQL） | **$0** | ✅ 正常 |
| B. AWS全家桶 | CloudFront | Lambda | RDS/DynamoDB | $5-30 | ✅ 海外节点 |
| C. 阿里云 | OSS+CDN | 函数计算FC | RDS MySQL | ¥50-200 | ✅ 但需ICP |
| D. 腾讯云 | CDN | 云函数SCF | TDSQL/MySQL | ¥50-200 | ✅ 但需ICP |

### 我的推荐：方案A（Vercel + Supabase）

理由：

| 维度 | 说明 |
|------|------|
| **成本** | V1期间**完全免费**（Vercel免费额度100GB带宽/月，Supabase免费50,000行+500MB存储） |
| **开发体验** | `git push`自动部署，不用管服务器 |
| **数据库** | Supabase = 托管PostgreSQL + 内置认证（Auth）+ 实时订阅 + 文件存储，**一站式解决** |
| **中国访问** | Vercel有亚洲节点，从中国访问延迟可接受（100-200ms） |
| **不需要ICP** | 海外部署，.com域名，无备案 |
| **后期迁移** | 数据是标准PostgreSQL，随时可以导出迁到AWS/阿里云 |

### 阿里云/腾讯云为什么不推荐V1用？

| 问题 | 说明 |
|------|------|
| **需要ICP备案** | 国内服务器必须备案，需营业执照或个人备案（时间长、限制多） |
| **成本更高** | 最低也要¥50-200/月，V1阶段没必要 |
| **国际访问差** | 如果卖家在海外，国内服务器对海外访问速度差 |
| **内容审查风险** | "帮你起诉亚马逊"这类内容可能触发审查 |

### AWS Lambda为什么不推荐V1用？

| 问题 | 说明 |
|------|------|
| **配置复杂** | 需要自己搞API Gateway + Lambda + DynamoDB/RDS，对独立开发者不友好 |
| **冷启动** | Lambda冷启动可能1-3秒，影响体验 |
| **成本** | 虽然理论上便宜，但零碎AWS服务加起来的账单很难预估 |
| **不如Vercel简单** | Next.js在Vercel上是一等公民，在AWS上需要额外配置 |

### 什么时候迁移？

| 用户量 | 方案 | 月成本 |
|--------|------|--------|
| 0-1,000 | Vercel + Supabase 免费层 | $0 |
| 1,000-10,000 | Vercel Pro + Supabase Pro | ~$45/月 |
| 10,000+ | 考虑迁移到自托管VPS或AWS | 视情况 |

**V1不需要考虑迁移。等真的有10,000用户了再说。**

## 三、数据库怎么搞？

### 推荐：Supabase（托管PostgreSQL）

Supabase不只是一个数据库，它是一整套后端基础设施：

| 功能 | 说明 | 是否需要额外搞 |
|------|------|---------------|
| **数据库** | PostgreSQL（最成熟的关系数据库） | ❌ 自带 |
| **用户认证** | 邮箱/密码登录、OAuth | ❌ 自带（Auth） |
| **API** | 自动生成REST和GraphQL API | ❌ 自带（PostgREST） |
| **文件存储** | 存文书模板PDF等 | ❌ 自带（Storage） |
| **实时订阅** | 数据变更实时推送 | ❌ 自带 |

### FreezeGuard需要的数据库表（很少）

```
users          — 用户信息（邮箱、创建时间）
cases          — 案件（平台、金额、冻结时间、类型）
assessments    — 评估结果（路径、时效、预估金额）
tasks          — 工作流步骤（状态、完成时间）
evidence       — 证据清单（名称、是否已有、重要度）
payments       — 付款记录
```

6张表。PostgreSQL处理这个连汗都不用出。

### 为什么不用DynamoDB/MongoDB？

| 数据库 | 问题 |
|--------|------|
| DynamoDB | AWS锁定、查询不灵活、需要提前设计访问模式 |
| MongoDB | 对这种结构化业务数据没有优势、多了一层复杂性 |
| MySQL | 可以用，但PostgreSQL更现代、Supabase直接集成 |

## 四、用什么语言？

### 推荐：TypeScript（不是Python，不是Java，不是Go）

| 语言 | 适合FreezeGuard吗 | 理由 |
|------|-------------------|------|
| **TypeScript** | **✅ 最适合** | 前端Next.js就是TS，后端API Routes也是TS，**一种语言搞定全栈** |
| Python | ⚠️ 可以但没必要 | V1不需要AI/ML，后端逻辑太简单用不上Python的生态优势 |
| Java | ❌ 太重 | 独立开发者用Java写这种产品是自虐 |
| Go | ⚠️ 过度设计 | Go适合高并发微服务，FreezeGuard V1根本不需要这种性能 |

### 为什么TypeScript是最佳选择

1. **一种语言全栈**：前端React/Next.js + 后端API Routes + 数据库查询（Supabase JS Client），全是TypeScript。不需要在语言之间切换
2. **类型安全**：问卷数据、规则引擎、支付回调——都有类型检查，减少bug
3. **生态最匹配**：Vercel + Next.js + Supabase + Stripe，这条技术栈的所有SDK都是TypeScript一等公民
4. **开发速度最快**：对独立开发者来说，一种语言 = 一套工具 = 最少的上下文切换
5. **V2需要AI时**：可以通过API调用Python AI服务，不需要把整个后端换掉

### 什么时候需要Python/Go？

| 阶段 | 场景 | 语言 |
|------|------|------|
| V2 | AI智能问答/材料分析 | Python（作为独立微服务，通过API对接） |
| V3 | 如果并发量暴涨需要极致性能 | Go（几乎不可能在V3之前需要） |
