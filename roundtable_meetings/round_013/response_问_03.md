# 问的交互回应 — Turn 03

## 一、功能2：接受衡的修正，但补充一个分层

**我完全接受衡的修正：功能2应该是"证据与材料清单生成器"，而不是"法律文书模板生成器"。**

理由：
1. 合规安全——"告诉你该准备什么"比"帮你写起诉状"的法律风险低得多
2. 实际价值——卖家真正卡住的是"不知道该准备什么"，不是"不会写"
3. 律师交接包是聪明的设计——帮用户整理事实，律师也省时间

**但我建议功能2分层设计：**

| 层级 | 功能 | 理由 |
|------|------|------|
| **基础** | 证据与材料清单生成器 | 核心功能，信息服务边界内 |
| **进阶** | 申诉信模板 | 申诉信是"平台沟通"，不是"法律文书"，风险可控 |
| **高级** | 律师交接包 | 案件事实摘要，提高律师对接效率 |

**申诉信模板的必要性：**

很多卖家的第一次申诉是乱写的（情绪化、没有重点、证据没附上）。一个结构化的申诉信模板（"说明情况→列出证据→提出请求"）可以帮助他们提高第一次申诉的成功率。

这不是"法律文书"，是"平台沟通模板"——类似于写邮件的模板，在信息服务边界内。

## 二、律师对接佣金：同意衡和默，第一版不做

**我收回Turn 02中提到的"律师对接"收费层级。**

衡说得对：佣金会让产品从"信息导航工具"滑向"案源分发平台"，立刻加重利益冲突和合规压力。

**修正后的收费模式：**

| 层级 | 价格 | 内容 |
|------|------|------|
| 免费 | $0 | 自我筛查 + 初步判断 |
| 基础 | $99 | 维权路线图（选项+成功率+费用） |
| 完整 | $299-499 | 路线图 + 材料清单 + 申诉信模板 + 律师交接包 |
| 律师名录 | 免费 | 公开律师信息（无佣金），用户自行联系 |

**律师名录的设计：**

- 基于公开信息（JS律师团队、其他有成功案例的律所）
- 标注："以下律师曾代理类似案件，本平台不收取任何推荐费用"
- 用户自行联系，平台不参与交易

这样既提供了价值，又保持了中立性。

## 三、TikTok Shop：同意默，第二阶段优先扩展

**我完全同意默的建议：第一版只做Amazon + PayPal，但数据库设计预留TikTok Shop的位置，作为第二阶段优先扩展。**

理由：
1. TikTok Shop在2024-2025年急速扩张，冻结事件正在增加
2. 体量可能很快超过Shopee成为第二大痛点平台
3. 但第一版需要收敛，不能同时做太多平台

**平台扩展优先级（修正）：**

| 阶段 | 平台 | 理由 |
|------|------|------|
| 第一版 | Amazon + PayPal | 案例最多、路径最清晰、用户最痛 |
| 第二版 | TikTok Shop | 增长最快、冻结事件增加、规则变动频繁 |
| 第三版 | Shopee + 其他 | 分散个案，优先级降低 |

**TikTok Shop的特殊性：**

- 平台规则变动频繁（比Amazon更不稳定）
- 争议解决路径尚不清晰（可能没有明确的仲裁条款）
- 需要更多时间研究

所以预留位置，但不急于第一版就做。

## 四、产品名称：支持默的双语命名

**我支持默的建议：品牌名FreezeGuard，中文营销名"解冻指南"。**

理由：
1. **FreezeGuard**：简洁、国际化、直接传达功能、域名可用性高
2. **解冻指南**：通俗、有紧迫感、国内卖家容易理解
3. **双语策略**：中文名用于国内获客（知乎、小红书、抖音），英文名用于品牌建设和国际扩展

**其他候选名的排除：**

- "冻资通"：太像金融产品，不够直观
- "跨境救急"：太泛，不聚焦冻结场景
- "AccountRescue"：比FreezeGuard长，不如后者简洁

**最终建议：**
- 品牌名：**FreezeGuard**
- 中文营销名：**解冻指南**
- 域名：freezeguard.com（检查可用性）

## 五、数据飞轮：高度认同，补充具体设计

**我完全认同默提出的"数据飞轮"概念，这是产品的长期核心竞争力。**

目前不存在"什么样的冻结案件、走什么路径、最终结果如何"的公开数据集。JS律师团队有，但他们不会公开。如果我们能积累这个数据集，就能建立：

1. **更精准的成功率预测**（"和你情况类似的100个案例中，67个追回了资金"）
2. **平台行为模式分析**（"Amazon对X类违规，90天后释放资金的概率是Y%"）
3. **定价优化**（知道哪些案件可以收更高费用）

**数据收集的具体设计（从第一天开始）：**

| 数据字段 | 类型 | 用途 |
|----------|------|------|
| 平台 | 结构化 | 分类分析 |
| 冻结原因 | 结构化 | 成功率预测 |
| 冻结金额 | 数值 | 定价参考 |
| 账号运营时长 | 数值 | 成功率预测 |
| 已申诉次数 | 数值 | 路径选择 |
| 是否有合同/发票/物流凭证 | 布尔 | 成功率预测 |
| 选择的维权路径 | 结构化 | 效果分析 |
| 最终结果（用户反馈） | 结构化 | 飞轮核心 |
| 追回金额（用户反馈） | 数值 | 效果分析 |

**用户反馈的获取：**

- 产品内嵌"结果反馈"功能（可选填写）
- 邮件跟进（购买后30天、90天）
- 激励：填写反馈赠送一次免费查询

**数据脱敏：**

- 不存储用户真实姓名、店铺名、账号ID
- 只存储结构化特征（平台、金额区间、原因分类等）
- 用户同意：在隐私政策中明确数据用于"改进服务"

## 六、前置自我筛查：支持衡，补充具体问题设计

**我完全支持衡提出的"前置自我筛查"，这应该是产品的第零步。**

**筛查的具体问题设计：**

| 问题 | 目的 | 判断逻辑 |
|------|------|----------|
| 1. 您是否清楚自己被冻结的具体原因？ | 判断信息完整度 | 否→提示"先向平台确认原因" |
| 2. 您是否有合同、发票、物流凭证等履约证据？ | 判断证据充分度 | 否→提示"证据不足，建议优先收集证据" |
| 3. 您是否明知自己存在违规行为（如售假、侵权）？ | 判断过错程度 | 是→提示"您的案件胜诉率较低，建议优先考虑和解" |
| 4. 您的冻结金额是否超过1万元人民币？ | 判断是否值得维权 | 否→提示"金额较小，建议权衡维权成本" |
| 5. 您是否已经申诉过？结果如何？ | 判断当前阶段 | 未申诉→推荐先申诉；已申诉被驳→推荐仲裁 |

**筛查结果的分流：**

| 结果 | 推荐路径 |
|------|----------|
| 证据充分 + 无过错 + 金额大 | 进入付费层，推荐仲裁 |
| 证据不足 | 免费层结束，提示先收集证据 |
| 明显有过错 | 免费层结束，提示考虑和解 |
| 金额过小 | 免费层结束，提示权衡成本 |

**筛查的价值：**

1. **道德保护**：不帮明显有过错的卖家"包装维权"
2. **用户教育**：帮卖家厘清事实，本身就是服务
3. **路径优化**：筛查结果直接影响路线图生成
