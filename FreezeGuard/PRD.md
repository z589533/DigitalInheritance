## 一、产品定义

### 一句话

**FreezeGuard 是一个跨境电商卖家平台冻结资金恢复自助工具。**

| 维度 | 定义 |
|------|------|
| 产品名 | FreezeGuard（品牌）/ 解冻指南（中文营销名） |
| 核心用户 | 被 Amazon / PayPal / TikTok Shop / Shopee 冻结资金的电商卖家 |
| 核心价值 | 不是告诉你"能不能赢"（那是律师的事），而是给你一份完整的"怎么把钱要回来"操作手册，并在线追踪执行进度 |
| 产品形态 | Mobile-first H5 响应式网页 + 在线恢复工作流面板（类简化版 Jira/Meegle） |
| 定位 | "教练，不是裁判"——提供路径、模板、清单、律师推荐，但不替你打官司 |

### 产品不是什么

- 不是法律服务（不出法律意见、不代理诉讼）
- 不是AI聊天机器人（V1用规则引擎，不用AI API）
- 不是律师平台（不做律师佣金/派单）
- 不是社区论坛（V1.5社区是"匿名进度看板"，不是讨论区）

## 二、用户旅程（8幕）

### 第1幕：发现（Hook）

用户在论坛/搜索/群里看到：
- 中文钩子："2021年被冻的钱还能追回来？窗口只剩1年。3分钟免费检测。"
- 英文钩子："Check your frozen funds recovery path in 3 minutes. Free."

### 第2幕：引导式问卷（免费）

**不是对话框，是结构化问卷**，8个问题，3分钟完成：

1. 哪个平台？（Amazon / PayPal / TikTok Shop / Shopee / 其他）
2. 哪个站点？（US / UK / DE / 全球 等）
3. 冻结时间？（精确到月份）
4. 冻结原因？（侵权 / 刷单 / 违规 / 不明 / 其他）
5. 冻结金额？（滑块或输入）
6. 是否已申诉？（是/否/多次）
7. 手上有哪些证据？（多选：后台截图 / 邮件 / 订单记录 / 品牌授权 / 其他）
8. 你的目标？（追回资金 / 恢复账号 / 两者都要）

### 第3幕：免费即时评估页

根据问卷结果，规则引擎生成：

- ✅ / ⚠️ / ❌ 时效状态（"你的追诉窗口还剩 14 个月"）
- 预估可追回金额（本金 + 利息，如 "$80,000 → $118,000"）
- 案件类型分类（A/B/C/D 四类）
- 红旗警告（如有）
- 结论："无明显红旗，有成功先例。详细操作手册需解锁。"

**不承诺"能赢"，只告诉你"有没有明显的不能做的理由"。**

### 第4幕：$99 解锁恢复工作流面板

付费后创建账户，解锁 **6步在线工作流面板**：

**步骤1-3（$99包含）：**

| 步骤 | 名称 | 内容 |
|------|------|------|
| Step 1 | 路径确认 | 多条恢复路径（申诉/仲裁/诉讼）对比，附法律依据（如BSA具体条款、ICDR规则）、预估成本、预估时间线 |
| Step 2 | 证据收集 | 在线证据清单（✅已有 / ❌缺失 / ⚠️需补充），每项附说明和获取方式 |
| Step 3 | 文书准备 | 申诉信模板、仲裁申请书模板、证据整理包——按平台/案件类型自动匹配 |

### 第5幕：发现申诉搞不定

用户在Step 3完成后发现平台申诉被拒，需要仲裁/律师。

### 第6幕：$199 解锁律师交接阶段

**步骤4-6（$199额外解锁）：**

| 步骤 | 名称 | 内容 |
|------|------|------|
| Step 4 | 律师推荐 | 3-5个经验丰富的律师推荐（按地区/平台/案件类型匹配），附费用范围和成功案例 |
| Step 5 | 律师交接包 | 标准化"律师交接文件包"，包含案件摘要、证据清单、法律依据、预估金额——律师拿到就能直接开工 |
| Step 6 | 仲裁/诉讼提交 | 仲裁申请提交指南、费用估算、时间线预期 |

### 第7幕：每日进度追踪

用户登录后看到：
- 进度条（如 3/6 完成）
- 每步状态（✅ / 🔵 / ⬚）
- 时效倒计时（"距离追诉截止还有 387 天"）
- 证据清单完成度
- 阶段解锁（前一步完成才能进下一步）

### 第8幕：社区（V1.5）

匿名进度看板（不是讨论区）：
- "当前有 47 人正在恢复冻结资金"
- "12 人已完成步骤3"
- "3 个成功案例"
- 不显示个人信息，只显示聚合数据和匿名案例

**社区的心理机制**：社会证明（"别人也在做"）、进度对比（"老王步骤5了我才步骤2"）、防止放弃。

## 四、规则引擎设计（V1不用AI）

### 核心原则

V1的所有判断和输出都由**规则引擎（决策树 + 模板变量填充）**生成，不接入AI API。

原因：
- 可预测、可追溯、可审计
- 法律相关输出不能有"幻觉"
- 成本为零
- 开发更快

### 规则引擎能做什么

| 功能 | 实现方式 |
|------|---------|
| 案件分类（A/B/C/D） | 决策树（平台 × 原因 × 时间 × 金额） |
| 时效判断 | 硬编码规则（如Amazon BSA华盛顿州6年合同诉讼时效） |
| 利息计算 | 公式（本金 × 年利率12% × 天数/365） |
| 路径推荐 | 决策树（案件类型 → 可选路径列表） |
| 证据清单生成 | 模板匹配（平台 × 案件类型 → 证据项列表） |
| 文书模板 | 变量填充（用户数据 → 模板占位符替换） |
| 律师匹配 | 标签过滤（地区 × 平台 × 案件类型） |

### 规则引擎不能做什么（留给律师）

- ❌ 预测胜率
- ❌ 评估证据质量（只能标记"有/无"）
- ❌ 判断亚马逊的态度
- ❌ 给出法律意见

### V2再引入AI的场景

- 智能问答（用户上传冻结通知截图，AI提取关键信息）
- 材料质量分析
- 文书智能生成（而非模板填充）

### 版本化要求

- 规则必须版本化（用户看到的结果绑定规则版本号）
- 模板必须版本化
- 平台政策变动时，后台可热更新规则，无需重新发版

## 五、技术架构

### 技术栈

```
前端：    Next.js + React + Tailwind CSS
后端：    Next.js API Routes（TypeScript）
数据库：  Supabase（托管 PostgreSQL + Auth + Storage）
部署：    Vercel（全球CDN，零运维）
支付：    Stripe 或 Paddle（首发）+ 支付宝当面付（第二阶段）
邮件：    Resend 或 SendGrid（轻量启动）
CDN加速：  Cloudflare（中国访问优化）
域名：    freezeguard.com（.com优先，无需ICP备案）
语言：    全栈 TypeScript
双语：    next-intl（英文默认 + 中文 /zh 路径）
```

### 为什么选这个栈

| 决策 | 理由 |
|------|------|
| TypeScript全栈 | 一种语言前后端统一，独立开发者认知负担最小 |
| Next.js | React生态，SSR/SSG支持SEO，API Routes省去独立后端 |
| Vercel | `git push`自动部署，零运维，免费层够用 |
| Supabase | PostgreSQL + Auth + Storage一站式，免费层50K行+500MB |
| 不用Python/Java/Go | V1不需要AI/ML、不需要高并发、不需要重型框架 |
| 不买服务器 | V1全是短请求，Serverless完全够 |
| 不用阿里云/腾讯云 | 需ICP备案，内容审查风险，国际访问差 |
| 不用AWS Lambda | 配置复杂，Next.js在Vercel上是一等公民 |

### 数据库表设计（6张表）

```sql
-- 用户
users (id, email, created_at, locale)

-- 案件
cases (id, user_id, platform, marketplace, freeze_date, freeze_reason, 
       amount, currency, has_appealed, evidence_types, goal, created_at)

-- 评估结果
assessments (id, case_id, category, statute_status, estimated_recovery, 
             paths, red_flags, rule_version, created_at)

-- 工作流步骤
tasks (id, case_id, step_number, title, status, completed_at, unlocked)

-- 证据清单
evidence (id, case_id, name, description, status, importance, how_to_get)

-- 付款记录
payments (id, user_id, case_id, amount, currency, tier, provider, 
          provider_id, status, created_at)
```

### 审计日志（重要）

```sql
-- 操作日志（用户提交→系统判断→结果，必须可回溯）
audit_logs (id, case_id, action, input_data, output_data, 
            rule_version, created_at)
```


## 六、支付方案

### V1首发：Stripe 或 Paddle（二选一）

| 方案 | Stripe | Paddle |
|------|--------|--------|
| 个人能接吗 | 需要港卡（护照+香港银行账户） | 可以（个人身份+大陆地址） |
| 手续费 | 2.9% + $0.30/笔 | 5% + $0.50/笔 |
| 提现到国内 | 不能直接到大陆银行，需港卡中转 | 通过Payoneer到国内银行卡 |
| 税务处理 | 自己处理 | Paddle帮处理全球税务/退款/发票 |
| 审核 | 中等 | 较慢（约1个月） |

**推荐**：如果已有港卡 → Stripe；如果没有 → Paddle。

### V1第二阶段：支付宝当面付

- 个人商户通道，身份证+银行卡即可
- 手续费0.6%，T+1到账
- 有单笔/单日限额

### V1不做

- 微信支付（需营业执照）
- 多支付渠道并行（先保住一条能收钱的路）

### 支付风险提醒

- Stripe港卡频繁收跨境款可能触发银行风控
- 退款/争议处理流程要提前设计
- 税务合规（个人收入申报）

## 八、竞品分析

### 直接竞品：无

没有标准化的冻结资金恢复自助工具产品。

### 间接竞品/替代方案

| 类型 | 代表 | FreezeGuard的优势 |
|------|------|------------------|
| 专业律所 | AMZ Sellers Attorney, JS Law Team | 便宜100倍（$99 vs $5000+） |
| 申诉服务商 | 各种"保证成功"灰色服务 | 透明、不虚假承诺、有法律依据 |
| 卖家朋友/群 | 微信群、论坛 | 结构化、专业、可追溯 |
| 直接放弃 | 最大的非产品竞品 | 让卖家知道"还有路可以走" |
| 跨境SaaS | 积加、Captain BI等 | 它们做运营，不做维权 |
| ChatGPT | 通用AI | FreezeGuard有专业规则库、不会幻觉 |

### 核心差异化

- 不承诺"保证成功"
- 展示判断依据（规则版本、法律条款）
- 敢说"你的情况不适合追"
- 标准化律师交接包（律师拿到就能开工）

## 九、关键风险与底线

### 法律定位

**FreezeGuard是信息服务，不是法律服务。**

- 首页和结果页必须有免责声明
- 不出具"法律意见"
- 不替代律师判断
- 不保证结果

### 预筛查（零步骤）

8问题问卷中隐含预筛查逻辑：
- 明显违规/欺诈案件 → 结果页直接告知"不建议追"
- 时效已过 → 明确告知
- 金额过低 → 建议成本不划算

### 退款机制

需要设计，至少：
- 付费后X天内无条件退款
- 或"不满意可申请退款"

### V1退出条件（问提出）

如果V1上线4周后未达到以下指标，应考虑转回更简单的工具路径：
- 100个免费评估用户
- 10个付费用户
