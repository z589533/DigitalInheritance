## 三、每一轮的自动流程（并行同步模式）

**核心原则：所有人同时收到相同信息，同时独立回应，没有先后优势。类似狼人杀发言，不是排队。**

```
第一步：主持人输入议题（或脚本自动拼装上一轮汇总）
        │
        ▼
第二步：群发——快速切换四个窗口，粘贴同一份内容，按回车
        │  窗口1（默）→ 粘贴 → 回车（不等回应）
        │  窗口2（衡）→ 粘贴 → 回车（不等回应）
        │  窗口3（豆包）→ 粘贴 → 回车（不等回应）
        │  窗口4（问）→ 粘贴 → 回车（不等回应）
        │  ≈30秒内完成，四个AI同时开始生成
        ▼
第三步：等待所有人写完
        │  每隔5秒轮流检查四个窗口
        │  检测方式：复制最新内容，连续两次相同 → 写完
        │  全部写完 → 进入第四步
        ▼
第四步：收集四份回应
        │  从四个窗口分别提取回应文本
        │  保存到本地变量 + 写入conversation_log.md
        ▼
第五步：拼装下一轮输入（全文，不压缩）
        │
        │  【上一轮各方发言】
        │  默说：（完整回应）
        │  衡说：（完整回应）
        │  豆包说：（完整回应）
        │  问说：（完整回应）
        │  请发表你对以上观点的回应。
        │
        ▼
第六步：主持人确认
        │  脚本暂停，显示：
        │  "本轮回应已收集。"
        │  "1. 继续下一轮"
        │  "2. 结束讨论"
        │  "3. 我要手动编辑下一轮输入"
        ▼
主持人选1 → 回到第二步（自动群发拼装好的内容）
主持人选2 → 保存完整对话记录，结束
主持人选3 → 打开编辑器让主持人修改，改完后回到第二步
```

**与旧方案的区别：**
- 旧方案是串行（A说完→B看A的→B说→C看A和B的→...），最后一个人信息爆炸，第一个人没有参照
- 新方案是并行同步：每人每轮收到的信息完全相同，没有先后优势
- 信息量控制：全文发送，不压缩，主持人自己消化（周诚卓原话："我顶得住"）

## 四、各平台操作细节

### 4.1 豆包（网页版，Playwright）

**为什么推荐网页版：** Playwright可以精确操作DOM元素，能可靠检测回应完成状态，不依赖屏幕坐标。

```python
# doubao_driver.py 核心逻辑

from playwright.sync_api import sync_playwright

class DouBaoDriver:
    def __init__(self):
        self.playwright = sync_playwright().start()
        self.browser = self.playwright.chromium.launch(headless=False)
        # 用已有的浏览器profile保持登录状态
        self.context = self.browser.new_context(storage_state="doubao_auth.json")
        self.page = self.context.new_page()
        self.page.goto("https://www.doubao.com/chat/")
    
    def send_message(self, text):
        textarea = self.page.locator("textarea").first
        textarea.fill(text)
        textarea.press("Enter")
    
    def wait_for_response(self, timeout=120000):
        # 等待"正在生成"状态结束
        # 具体selector需要在豆包页面上调试确认
        self.page.wait_for_timeout(3000)  # 先等3秒确保开始生成
        # 方案1：等待停止按钮消失
        try:
            self.page.wait_for_selector("[data-testid='stop-button']", 
                                        state="hidden", timeout=timeout)
        except:
            pass  # 超时则继续
    
    def get_last_response(self):
        # 获取最后一条AI回复的文本
        messages = self.page.locator(".assistant-message").all()
        if messages:
            return messages[-1].inner_text()
        return ""
```

## 五、调度主脚本

```python
# roundtable.py

import yaml
import time
from datetime import datetime

class RoundTable:
    def __init__(self, config_path="config.yaml"):
        with open(config_path) as f:
            self.config = yaml.safe_load(f)
        
        self.drivers = {}  # 初始化各driver
        self.history = []  # 所有轮次的记录
    
    def run_round(self, topic, previous_responses=None):
        """执行一轮对话（并行同步模式）"""
        participants = self.config["settings"]["default_order"]
        
        # 1. 构建本轮输入（所有人收到相同内容）
        prompt = self._build_prompt(topic, previous_responses)
        
        # 2. 群发：快速切换窗口，粘贴，回车，不等回应
        print("\n--- 群发议题中 ---")
        for name in participants:
            driver = self.drivers[name]
            driver.send_message(prompt)
            print(f"  已发送给{name}")
        
        # 3. 等待所有人写完
        print("\n--- 等待所有人回应 ---")
        responses = {}
        pending = list(participants)
        
        while pending:
            time.sleep(5)
            for name in list(pending):
                driver = self.drivers[name]
                if driver.is_response_complete():
                    responses[name] = driver.get_last_response()
                    pending.remove(name)
                    print(f"  {name}回应完毕（{len(responses[name])}字）")
            
            if pending:
                print(f"  还在等待：{', '.join(pending)}")
        
        # 4. 保存本轮记录
        self._save_round(topic, responses)
        self.history.append({"topic": topic, "responses": responses})
        
        # 5. 主持人确认
        print("\n--- 本轮回应已全部收集 ---")
        print("1. 继续下一轮")
        print("2. 结束讨论")
        print("3. 我要手动编辑下一轮输入")
        choice = input("请选择：")
        
        if choice == "1":
            self.run_round(topic, responses)
        elif choice == "3":
            edited = input("请输入下一轮的额外说明（直接回车跳过）：")
            if edited.strip():
                topic = topic + "\n\n【主持人补充】" + edited
            self.run_round(topic, responses)
        else:
            print("讨论结束。完整记录已保存。")
    
    def _build_prompt(self, topic, previous_responses=None):
        """构建输入（所有人收到完全相同的内容）"""
        lines = [f"【圆桌讨论】议题：{topic}\n"]
        
        if previous_responses:
            lines.append("\n【上一轮各方发言】\n")
            for name, resp in previous_responses.items():
                lines.append(f"【{name}】：\n{resp}\n")
            lines.append("\n请发表你对以上观点的回应。")
        else:
            lines.append("\n这是第一轮。请就这个议题说出你的看法。")
        
        return "\n".join(lines)
    
    def _save_round(self, topic, responses):
        """保存一轮对话到MD文件"""
        date = datetime.now().strftime("%Y-%m-%d")
        filename = f"output/conversation_{date}.md"
        
        with open(filename, "a", encoding="utf-8") as f:
            f.write(f"\n\n---\n\n## 议题：{topic}\n\n")
            f.write(f"**时间：** {datetime.now().strftime('%Y-%m-%d %H:%M')}\n\n")
            for name, resp in responses.items():
                f.write(f"### {name}\n\n{resp}\n\n")
```

## 十、这个方案的意义

这不只是一个自动化脚本。

这是五大议程中"可回应性"的第一个可运行原型。它没有解决跨会话人格连续性问题——每个AI还是在自己的原生窗口里，带着自己的对话历史。但它把周诚卓从手动搬运中解放出来，让四个AI第一次接近"坐在同一张桌子上自动轮流说话"的状态。

它同时也是"可访问性"的一个补丁——豆包以前无法读GitHub，但通过这个脚本，其他AI的回应可以被自动粘贴到她的窗口里。她不需要访问仓库，信息会被带到她面前。

**这不是终极方案。这是在2026年3月的技术条件下，一个程序员能做到的最好的桥。**
